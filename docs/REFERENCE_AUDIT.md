# Implementation audit against the concept-subspace reference

Audited 19–20 October 2026 against the framework paper ([Naowarat, Tang & Goldwater 2026](https://arxiv.org/abs/2605.01381)) and its reference code ([burin-n/concept_space @ b4f89a4](https://github.com/burin-n/concept_space/tree/b4f89a4667af6b95d1477506ad0d3bd62d5e381a): `concept_space/LEACE.py`, `projector.py`, `helper/helper.py`, `evaluate.py`, `run_acl_test_suite.py`, `gather_results.py`). The starting point was the previous version of this pipeline (v3 below); the audited version (v4) is the one released here and the one that ran every experiment.

## How the comparison was done

The reference operators were re-implemented directly from the reference source (`check_reference.py`-style script, kept out of the repository) and compared with `idiom_subspace.geometry` on controlled synthetic data with anisotropic noise. Following `evaluate.py`, the reference trains its probe on the **ambient-dimensional output of `proj.projection(X)`** for retention and on `X − proj.projection(X)` for leakage, with `LogisticRegression()` defaults. Our pipeline trains on compact coordinates; for L2-regularized logistic regression this is equivalent only if the compact coordinates are an isometry of the ambient projected vectors, which was checked numerically.

## New findings in this audit

1. **Split policy.** The v3 "strict" split linked records through *every* listed English counterpart. Only the first counterpart is ever a model input, but transitive linking through secondary counterparts creates one component with 66% of the corpus. That component must sit in SPACE, which (a) makes SPACE a single permutation bundle, so the label-permutation null is impossible, and (b) leaves a test set that over-represents religious (17.1% vs 12.9%), historical (8.0% vs 5.6%) and rare (21.8% vs 17.5%) idioms. Conversely, v3 did **not** link identical glosses or example sentences, so identical `en-para`/`bn-para` inputs could appear in two splits (1,544 cross-split identical inputs without such links). v4's `input_disjoint` default links exactly the records that would otherwise share an idiom type or an identical model input: largest component 8.7%, zero identical inputs across splits, representative splits, 1,914 exchangeable SPACE components. See [DATA_AUDIT.md](DATA_AUDIT.md). The v3 policy is kept as `configs/counterpart_closure.json`.
2. **MLR and RAND deviated from the reference** (table above).
3. **The analysis stage was computationally infeasible.** The GPU log of a v3 run showed ~8 h for 12 of 26 subspace pairs of one concept at one layer. In v3 as first written, every rank refitted MLR and a full PCA SVD and transformed all 81k rows twice per readout; v3 removed those redundancies, but the full design still requires ~4,400 probe fits per layer per refit plus up to 1,999 permutation draws that each refit MLR. v4 adds a batched GPU engine (`idiom_subspace/fastprobe.py`) that minimizes exactly scikit-learn's L2 logistic objective with per-problem L-BFGS (independent curvature pairs, step sizes and convergence per problem) and computes erased/ambient features as low-rank corrections of one shared matrix. With shared estimators it reproduces the scikit-learn study outputs exactly (`test_torch_study_matches_sklearn_when_estimators_are_shared`). `probe_backend="auto"` uses it on CUDA; scikit-learn remains the CPU default and the reference check. Converged fits replace the reference's `max_iter=200` cap, so results do not depend on optimizer details.
4. **Truncated subspaces can be ill-determined.** When consecutive singular values are nearly tied, the rank-M prefix rotates between two equally valid fits (seen in the synthetic fixture: 1.2266 vs 1.2229). v4 records `spectral_gap = (s_M − s_{M+1})/s_M` for every grid row and subspace-overlap row; interpret low-gap ranks with care.
5. **The English-anchoring moderator was degenerate.** 98.8% of records list a counterpart, so `anchored` cannot carry an anchoring contrast. v4 adds `cp_transparency` (cosine between the probed counterpart and the English gloss under the never-probed taxonomy encoder; tertiles fitted on SPACE) and the `transparent − opaque` contrast. It is a covariate, not a label. Under en→bn transfer the test idiom's own counterpart never enters the computation, so associations reflect Bangla-side correlates of transparency.
6. **S4a could not run.** L requires English literal glosses; none exist in the corpus. v4 adds `translate-literals` (machine translation, provenance-tagged, human rows take precedence).
7. **Small-sample whitening in the open-class sweep.** With full hidden dimensions the open-class estimation sets (N = 50–3,200 types) often have fewer rows than dimensions, making LEACE/LDA whitening degenerate (a dip earlier attributed to conditioning). v4 applies Ledoit–Wolf shrinkage to LEACE/LDA in the sweeps (`open_class_ridge`, recorded per row); the main grid, estimated on all of SPACE, is unchanged.
8. **Planned items not yet implemented.** S4b's containment/purity trade-off had no purity measure, and the open-class identity concept I had no implementation. v4 adds purity to the open-class sweep and an identity study (`configs/identity_openclass.json`, `S4_identity.csv`) in which identity subspaces estimated on SPACE idioms must match the two contexts of unseen TEST idioms. Span-level identity is largely lexical (both contexts contain the same string; on the real-data check, ambient top-1 = 0.96 and random 64-d subspaces reach 0.89), so the study also reports idiom-masked contexts, which test semantic identity.
9. **Robustness of long runs.** Capped scikit-learn fits printed a multi-line warning each (and were otherwise invisible); they are now recorded per readout (`probe_converged`). Checkpoint identities hashed the source files at every layer, so editing or pulling code mid-run silently invalidated later checkpoints; the digest is now fixed per process. Task context in `progress.json` is reset per stage.
10. **S2 used a one-dimensional language direction.** v4 adds a multi-dimensional language subspace from paired translation differences (`S2_language_subspace.csv`: concept information inside/outside it and principal angles to the concept subspace) and an alignment-free cross-lingual measure, principal angles between separately estimated subspaces (`S3_subspace_overlap.csv`).
11. **Solver precision.** Readout probes and MLR estimators are solved to the same gradient tolerance (`LOGISTIC_TOL = 1e-5`) in both backends. scikit-learn's default (1e-4, which the reference inherits) leaves low-rank MLR directions solver-dependent. On real mBERT features (layer 6, concept F, true and permuted labels), rank-1 subspaces had mean cos² 0.974–0.98 with the exact optimum at 1e-4, against ≥ 0.9993 at 1e-5. On CUDA the engine runs in float32. Near the optimum, objective decreases fall below float32 resolution, so fits stop at gradients of about 3e-5 to 2e-4. Such stops count as converged, as scipy's relative-reduction stop does; iteration caps and line-search failures do not. Before this change the flag marked about 95% of float32 fits as unconverged. With float32 emulated on CPU on the same data, the torch probes and estimators matched the scikit-learn study outputs: identical SSI and p-values, RAND/PERM null means within 0.003, and retention within one test item. In low-signal cells one flipped item moves SSI visibly (0.03 on the 322-item mini test set), so compare reruns on different backends within the bootstrap CIs.

## Verification performed on a CPU machine

- Full test suite (unit, integration, dashboard HTTP, launcher, extraction with tiny local models, and the new engine-equivalence tests).
- `smoke_offline.py` with both probe backends: real extraction, S1–S4, and a resume that loads no weights and refits nothing.
- A real-data run on a 1,500-record Bagdhara subset with pretrained mBERT on CPU (`probe_backend=torch`), covering spans, normalization, the new split, MiniLM labels, all studies and the dashboard. This verifies the implementation, not research findings.
- GPU numerics emulated on CPU: on cached features from that run, float32 torch probes and estimators were compared with scikit-learn and float64 torch, at the study level and fit by fit (finding 11).

GPU throughput and the pretrained full-corpus results came later, from the GPU campaign.

## Deployment follow-up, 20 October 2026

The final recorded validation was **143 tests passed**, plus successful offline extraction/resumption with both probe backends and the real-data mini run. The source/config/test files were unchanged after that passing run when this follow-up began. Those audits and tests were reused, not rerun.

A narrow check of untested batching modes found three workflow issues: Torch prefetch fitted nonzero-draw readouts twice without checkpoints, did the same with `resume=False`, and prepared every permutation estimator/factor before readout chunking. The follow-up changes only prefetch scheduling: nonresumable modes use the existing scalar Torch path, while normal resumable batches prepare factors within each chunk and release transient estimators even for unavailable tasks or exceptions. Optimizer, estimator definitions, defaults and inference formulas are unchanged. A transient estimator can be refitted for another target group in exchange for bounded working memory.

Four new mocked regression cases in `tests/test_gpu_readiness.py` passed, covering those paths, key deduplication, evidence restoration and bounded permutation state. A separate read-only review found no blocker in the patch. The existing full suite and neural smoke runs were not repeated. Use a fresh analysis output after this source update; completed raw representation caches remain reusable.

The single-GPU command must include `--gpus 0`. Optional 4-bit loading needs `requirements-decoder.txt`; default bf16 does not.
